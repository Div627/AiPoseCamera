# 拍摄地点推荐与情绪 Vlog 实施计划

状态：实施前计划；以下能力尚未完成。默认服务对象为小米 17，保留原有简洁相机体验。

用户明确约束：以每段对话作为本地拍摄项目，聊天、计划、素材与成片保存到手机，不做云端存储。视频素材不默认上传；合成在手机执行。

## 用户体验

从相机的一个「去拍什么」入口开始，支持输入文字，语音作为后续增强。用户说「我到冰岛了，想拍风景」或「拍一段从孤独到有生命力的旅行视频」，系统理解意图，读取用户主动授权的当前位置，生成可执行建议。拒绝定位时允许输入城市或地图选点；不申请后台定位。

主流程只需要三步：描述想法 → 选择地点或拍摄方案 → 拍摄并生成作品。相机默认风景、原有人像/风景模式继续保留；新功能用底部面板和独立任务页承载，不让主取景界面常驻一排新按钮。

## 聊天到相机的具体闭环

第一版增加「AI 拍摄助手」入口，打开简洁对话页。相机仍是默认首页，助手不会变成每次拍照的必经流程。输入「我到了冰岛，想拍有层次的风景」，助手先区分任务是拍照、找地点还是拍 Vlog；可一次生成相关方案，但不凭国家名猜测当前位置或天气。

对话结果不是一大段教程，而是可点击的方案卡：一句风格说明、一句拍摄建议，以及「开始拍摄」；地点推荐另外提供「去这里」，避免把导航与相机启动混在同一个按钮。第一版首推一个自然方案，另给最多两个可选风格；不要求用户选择品牌或调节一组参数。

示例卡：自然纪实风景，保留雪山亮部、暗部不过度提亮，找一处前景增强层次。用户若明确要冷峻低饱和，提供克制冷调作为选择；不因目的地是冰岛就默认所有照片套冷色滤镜。示例只是产品设计，具体方案应结合意图与可确认的现场信息。

点击「开始拍摄」后，先保存方案，再切回相机并一次性应用风景/人像模式、已支持的风格、滤镜强度和允许范围内的调色设置。视场/倍率需设备支持才应用；没有合理依据不自动放大。快门仍由用户控制，照片原片保留。

进入取景后保留一条「正在用自然纪实」提示，并给「换风格」和「恢复自动」入口。实时图像分析继续保护高光、判断稳定度和更新构图建议；现场光线变化不应被聊天时的静态参数锁死。

### 状态与执行边界

- 新增对话与拍摄方案状态层，方案含唯一身份、任务类型、风格意图、可应用设置、场景建议与来源。导航传递方案身份，避免将大量内容直接塞进路由；草稿与相机状态可恢复。
- AI 输出结构化方案，经本地白名单与范围校验后才执行。模型只能从现有能力中选择，不能执行任意命令，也不能生成未经核验的坐标或不存在的滤镜。
- CameraScreen 的风格、调色与模式从方案初始化。当前多个 remember 状态及绑定重置逻辑需整理，保证同一方案只应用一次，旋转/重绑/从相册返回不会反复覆盖用户修改。
- 选定风格与现场自适应分离：固定用户选择的风格基底，保留有边界的曝光保护；现有自动模式仍可继续完全自动重选风格。避免当前 autoStyle 将助手选定风格覆盖的问题。
- 已支持的是模式、风格、后期调色、倍率与设备开放的曝光补偿。第一版不宣称已支持手动 ISO、快门或传感器白平衡；需要长曝光的方案明确提示现有能力限制，不输出无效「已应用」。
- 返回结果区分「推荐」「正在应用」「已应用」「部分设置不可用」，不在相机未绑定或执行失败时提前显示成功。无网络时仍可用本地方案与已有相机，不显示伪造 AI 回复。

### 第一条闭环的验收

先做文字聊天 → 方案卡 → 进入相机 → 真正应用风格 → 拍照保存 → 返回原对话。使用可控回复测试配置有效性、自动算法不会覆盖选定风格、不支持能力会回退、反复进出不丢方案。公开版还需接通真实服务端后才能交付联网 AI；测试替身不能冒充完成。

随后将同一入口延伸到「推荐地点 → 导航 → 对应方案拍摄」与「情绪需求 → 分镜卡 → 视频素材 → 自动成片」。不另建一套互不相通的聊天、地点和视频功能。

地点推荐首屏最多三张卡片，显示地点、推荐理由、经路线服务核验的交通时间、适合拍摄的时间段、来源与导航入口。参考照片必须标明来源和许可；没有可使用的照片时显示地图或文字，不伪造现场样片。只知道国家不能当作精确位置。

Vlog 默认竖屏约 30 秒、约 6 个镜头，提供「更短 / 更长」「横屏 / 竖屏」轻量选择，不要求填写表格。每张镜头卡只给拍什么、怎么移动手机、建议拍多久；一次突出一个镜头，完成后自动进入下一张。允许跳过、补拍和从相册导入。

## 对话渲染、Markdown 与卡片交互

性能优先采用 Compose 原生长列表，消息使用稳定身份，仅渲染可见项；避免每次内容增加时重建整个消息列表或重新解析全部 Markdown。长对话按页加载，缩略图按显示尺寸解码与缓存，不将全尺寸照片或视频帧放进聊天列表。

接入流式服务后，以短时间窗口合并增量更新，只更新正在接收的消息。已完成 Markdown 分块解析并缓存；活动消息尚未闭合的代码块、列表或表格按稳定的回退样式展示，不让布局随每个字符大幅跳动。解析在后台执行，第一版支持段落、标题、强调、列表、链接、引用和代码块；复杂表格横向滚动，语法高亮按需启用，避免主线程长文本处理。Markdown 库选型需先核对许可、维护与 Compose 长列表性能，再在样例中验证，当前未选定。

用户在底部时才自动跟随新消息，正在阅读旧消息时显示「新回复」入口；键盘弹出、返回相机、流式结束均保持合理阅读位置。支持停止生成、重试、复制和失败状态；网络请求取消与重试不重复创建项目或应用相机方案。

拍照方案、地点与镜头卡采用原生 Compose 组件，根据经校验的结构化数据渲染，不从 Markdown 文字里猜按钮或执行参数。卡片具备未准备、可执行、应用中、完成、失败/素材缺失等明确状态，点击区域与加载反馈一致，避免连续点击重复导航、录制、生成或保存。回到对话后状态来自本地项目，不因组件重新渲染丢失。

验证使用长对话、长 Markdown、混合卡片、持续增量回复、大量缩略图、键盘和快速滚动场景，记录掉帧、首屏时间、内存及解析耗时，与纯文本基线比较。模拟器仅用于功能与初步性能排查；小米 17 的滚动帧率不能未经测量承诺。卡片对应的相机设置与导出结果必须实际验证，不能用流畅演示替代执行成功。

## 模型现状与接入

代码的默认提供商是 DeepSeek，默认模型标识 deepseek-chat；备选通义千问 qwen-plus。现有 LlmClient 仅发送系统提示与当前文字，不是完整多轮对话，也没有流式实现。公开构建中的个人密钥为空，新对话功能尚未接通服务；这些是本地代码事实，不是当前供应商模型排名或质量结论。

对话模块增加可替换的提供商接口、流式取消、历史上下文整理与结构化输出校验。长对话按项目事实和近期消息组织请求，避免无限携带历史；本地仍保留完整记录。公共版通过配置好的服务端代理调用，凭据留在服务端，不写 APK、不要求用户在聊天里粘贴 Key。

不先假定更贵模型必然更好。以相同摄影意图、地点候选和 Vlog 素材描述比较计划可执行性、输出格式、延迟、费用与叙事质量，再决定主模型与回退模型。若后续要理解实际图片/视频，另行核验多模态能力和本地素材约束；现有文字接口不能冒充视觉分析。联网服务仍需可用服务配置，不能拿无凭据的当前公共包宣称聊天可用。

## 按对话组织的本地视频项目

对话生成 Vlog 方案后，直接显示可填充的镜头卡，例如「空旷远景」「独行背影」「光或水的细节」「动态生活」「人物互动」「开阔收尾」。卡片状态为未拍、已有素材、需补拍或已跳过，显示缩略图与时长；未拍卡提供「拍这一段」和「从相册选」。用户能换素材，不需要先理解时间线。

录制返回后素材归入当前对话的当前镜头卡，并更新完成数；不会要求把视频发送到云端。达到最少可成片条件后显示「生成视频」，缺镜头时允许补拍或基于现有素材缩短方案，不强制必须拍满固定模板。生成后在同一对话里显示可播放成片，提供「换一个片段」「重新生成」「保存到相册」。

本地项目列表可从助手入口进入，每项显示对话主题、最后进度和缩略图。对话文本、方案、镜头对应关系、编辑决策和版本保存在本地数据库；录制素材、缓存与草稿输出放在应用文件区，用户主动保存的成片写入系统相册。

相册导入素材取得持久读取权限；来源不支持持久权限时复制到本地项目，不能只存一个可能失效的临时 URI。若用户删除外部原素材，项目明确显示缺失并允许重新选择。生成时检查可用空间，支持取消；先写临时文件，成功验证后替换结果，失败不破坏上一版。

删除项目时明确区分应用管理的副本与系统相册原片/已导出的成片，不连带删除用户原素材。应用卸载会移除应用文件区与本地数据库；主动保存到相册的成片按系统相册管理。

联网 AI 只承担文字意图与分镜规划，地图等服务负责地点信息，相关请求仅在使用对应功能时发出。这与本地保存是不同维度，不能宣称已经是完全离线 AI，或保证第三方服务从不保留请求。第一版本地视频剪辑依据分镜对应关系和端上可实现的媒体分析；需要将原视频传到远程模型的理解能力暂不启用。

## 示例：从孤独到有生命力

这是叙事示例，不是对当前冰岛天气、道路或地点的实时推荐。

| 段落 | 画面方向 | 拍摄动作 | 成片作用 |
| --- | --- | --- | --- |
| 开场 | 空旷景色，主体较小 | 固定机位，留一拍空间 | 建立孤独与距离 |
| 延续 | 一个背影或独自行走的脚步 | 稳定拍摄，不追求复杂运镜 | 引入人的存在 |
| 转折 | 光线、流水或植物细节 | 缓慢靠近，拍清变化 | 从静止过渡到活动 |
| 展开 | 水流、树叶、当地生活等动态 | 拍动作发生前后完整片段 | 增加节奏与生命感 |
| 高点 | 人与环境互动 | 选择明确动作，留剪辑余量 | 情绪释放 |
| 收尾 | 开阔景色或继续前行 | 稳定收尾，避免突然停录 | 留下延伸感 |

素材一般建议单镜头录 6–10 秒，剪辑保留约 3–6 秒；具体随故事和素材调整。人物或动态元素不在现场时，改用可拍的光、水、风等内容，不把模板变成硬性要求。

## 实施顺序

### 第零阶段：先验证热门开源能力与效果

用户要求优先选择 Star 较高、适合个人 Vlog 的 skill，不能仅凭模板名称或宣传演示接入。2026-10-07 通过 GitHub API 与各仓库 README 核对：

| 候选 | 当次 Star | 已核验用途 | 本项目判断 |
| --- | ---: | --- | --- |
| [Remotion 官方 skills](https://github.com/remotion-dev/skills) | 4,867 | Remotion 工程最佳实践、制作与渲染 | 热度较高，但偏程序化制作；不等于个人 Vlog 导演或 Android 编辑 SDK。许可需单独核对 |
| [剪映 editor skill](https://github.com/luoluoluo22/jianying-editor-skill) | 3,776 | 国内桌面剪映草稿、特效、字幕；Mac 手动导出 | 不支持手机剪映，不作为 Android 自动成片的运行依赖；许可仍需审查 |
| [FireRed-OpenStoryline](https://github.com/FireRedTeam/FireRed-OpenStoryline) | 3,464 | 意图驱动剪辑、素材理解、旅行 Vlog 示例、可复用编辑 skills | 优先核验分镜和编辑流程参考价值；项目 Apache-2.0，外部模型与素材需各自核对。需后端，不可直接作为 Android 库嵌入，不默认启用素材上传 |

Star 为关注度而非安装人数或质量证明，上表不是完整社区排名。当前仅检索、阅读了元数据与文档，尚未安装或验证成片。热门录屏、商品图生成与游戏摄影项目虽被搜索命中，但用途不匹配，不据此接入。

拍摄指导方面，本次未找到同时具有较高 Star、明确适用真实手机人像/风景拍摄、且有可核验效果评测的现成 skill。公开摄影后期 skill 不等于相机现场指导；不能因此断言社区完全没有合适项目。

效果优先的验证安排：

1. 先准备约 20 个摄影场景与至少 6 组个人/旅行短视频素材，覆盖逆光、夜景、肤色、平淡素材、缺少某段镜头、混合方向等问题。素材与许可留档；测试集分开发调试和留出验证，避免同一批样片反复调参后充当泛化证明。
2. 同一输入分别运行现有方案、候选开源方案与必要的自建方案。保存完整建议、实际输出、失败原因、运行时间与资源消耗，标记模型版本与依赖。
3. 摄影评估同时看可执行指导、构图、肤色、曝光、真实感；图片回放能测处理结果，不能证明按提示走位后更好看，后者需要可控场景或真实拍摄对照。
4. 视频评估看镜头选择、情绪转折、重复与空镜、节奏、自然声、字幕、音画同步和输出完整性。「孤独到有生命力」不能简化成先冷后暖滤镜。
5. 采用隐藏方案名称的对比展示；AI 评分只作辅助，技术指标通过也不等于审美胜出。尚无独立人类评审时明确报告，不自称已完成盲评或证明大师级质量。
6. 如果热门候选不适用或未优于基线，再创建专用的拍摄指导与个人 Vlog 导演 skill，包含参考规则、反例、结构化输出和可重复评测。每轮修订只在开发集调优，再检查留出集；不因有 SKILL.md 就认为效果提升。

通过这一步确定可迁移的分镜与编辑策略。受用户本地存储与本地合成约束，Android 本地编辑按 Media3 等运行时模块单独实施，不采用上传视频到云端的成片后端；开发助手的 skill 与用户手机内的执行能力保持清晰边界。

### 第一阶段：地点推荐与分镜计划

1. 定义地点、来源、路线、拍摄条件、镜头计划和任务进度的数据结构，保存草稿并支持恢复。
2. 增加前台定位与城市输入，处理拒绝授权、无定位、弱网及国外服务可用性。
3. 接入可检索真实地点与来源的服务，分开处理地图地点、道路路线、天气和官方开放信息。优先附近、可到达且符合拍摄意图的候选；无法查证的信息明确为未知。
4. 云端 AI 将用户描述转成结构化兴趣与情绪走向，并基于已检索候选生成理由和分镜；禁止由模型自由编造坐标、行车时间或开放状态。
5. 完成最多三项推荐、导航入口、分镜清单、已拍/跳过/补拍状态。定位偏移或建议过期后重新获取，不把直线距离标为驾车时间。

验收：模拟不同城市、无权限、无网络、未知路线等输入；结果来自候选数据，分镜可执行，退出重进不丢任务。需要为公共包配置可运行的服务后端；不能仅有演示数据就宣称线上推荐可用。

### 第二阶段：素材导入与自动成片

1. 先支持系统相册导入视频并对应镜头卡，用户已有视频即可验证完整剪辑流程。
2. 增加本地编辑模块：读取方向与时长、统一输出比例，选片段、排序、裁切与拼接，生成可预览草稿。默认 1080p，保留全部原素材。
3. 第一版优先明确的镜头顺序和稳妥剪辑规则。运动、清晰度、黑帧与重复素材检测分步加入，低置信度允许用户换片段；未实现的理解能力不以「AI 已看懂」包装。
4. 简单操作为「生成」「换一个片段」「重新生成」「保存」，高级时间线不作为默认流程。
5. 音乐只使用随包授权或用户自行导入的素材；无音乐仍可输出。先打通顺剪、自然声与简单淡入淡出，再做节拍匹配和精细转场。

验收：真实短视频输入覆盖旋转、混合比例、不同帧率、无声轨、损坏素材与低存储；导出视频可播放，音画同步，可取消，失败可重试，后台/进程恢复不损坏原素材。对「孤独到生命力」检查镜头顺序和节奏是否呈现转折，不用一句模型评分当作艺术质量证明。

### 第三阶段：应用内引导录制

1. 增加 CameraX 视频录制与音频权限，录制参数单独管理，避免影响照片拍摄。
2. 当前镜头卡进入取景：显示一句运镜提示、计时和录制按钮，拍完直接记录进度。
3. 新录素材与导入素材共用第二阶段的生成流程。处理被电话打断、暂停恢复、切镜头与存储不足。

验收：压缩 ARM64 发布包的录制、保存、导入与导出链路。模拟器验证 UI 和流程；小米 17 录制稳定性、发热、真实收音及画质仍需要实际设备验证。

## 技术路线与依赖

采用文字规划联网、项目与媒体全本地的架构：联网获取地点、路线、天气与 AI 分镜，本地保存对话和任务、处理素材并导出视频。不建设云端项目库，不默认上传照片或视频，不以云端剪辑替代用户要求的本地合成。

Android 视频候选采用 CameraX Recorder 与 Media3 Transformer。接入前核对官方文档、最低 Android 版本、现有 CameraX 兼容性和具体效果支持；不预先承诺未验证的转场或编码能力。服务层采用可替换接口，避免 UI 绑定某一家地图或模型供应商。

当前仓库没有地点推荐服务、视频录制或编辑依赖；现有公共包也没有个人模型密钥。公共版需要服务端持有供应商凭据，不能把个人 API Key 加回 APK。供应商选型先做覆盖、费用、许可和可用性核验，不在计划阶段声称已接通。

## 自主验证与交付

准备可合法使用的地点数据和短视频测试素材，保留来源，回放生产逻辑。每阶段运行对应单测、release 构建和 lint；通过 APK 安装与实际导出回读核验结果。公开测试数据仅用于测试，不混入真实推荐。

每个可交付 beta 保持包名与签名兼容，递增版本号与 versionCode，附经下载校验的 HTTPS APK 二维码。第一阶段验证通过后再展开剪辑，不同时堆出多个半成品页面。此计划不承诺上线日期或摄影比赛级结果。
